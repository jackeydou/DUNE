# Tech stack

The libraries and tools SwarmEval uses. Installed today: Python 3.12, uv, ruff, pyright,
pytest, pydantic, PyYAML (with `types-PyYAML` for pyright), `inspect_ai` (pinned), SQLAlchemy,
Alembic, psycopg 3, `rfc8785`, pyarrow (with `pyarrow-stubs` for pyright), grpcio and protobuf
(with grpcio-tools and mypy-protobuf for stubs), and testcontainers; Go 1.27, golangci-lint, buf,
grpc-go, connect-go, and the moby client. Everything else arrives with the service that needs it; [architecture.md](architecture.md)
says which milestone that is.

This page covers tooling and the choices shared across services. The libraries one service uses
alone, and why, are on that service's page (see [Per service](#per-service)). Why the stack is
shaped this way is in the v1 spec's 技术选型 table and the
[runtime spec](../spec/2026-09-28-runtime-sandbox-logs/README.md).

## Tooling

| Area | Choice |
|---|---|
| Tool versions and tasks | mise. `mise run check` is the gate for every change ([development.md](development.md)) |
| Python | uv for dependencies and the lock file, ruff, pyright in strict mode, pytest + pytest-asyncio |
| Go | go test, golangci-lint (with gofumpt and goimports), all in `mise run check` |
| gRPC contracts | buf: lint, Go code generation (grpc-go and connect-go), and breaking-change checks on the public API. Python stubs come from grpcio-tools, with `.pyi` from mypy-protobuf, because Python protobuf generation is built into `protoc` and buf would need a separate `protoc` install for it |

## Shared by the Python services

`orchestrator`, `model-gateway`, and `analysis` are one uv project.

| Area | Choice |
|---|---|
| Runtime | Python 3.12, asyncio |
| Case, env, and event models | pydantic v2 + PyYAML. JSON Schema is exported for editor validation |
| Event format | `inspect_ai` data models at a pinned version, imported only in `swarmeval/events/` ([event-log.md](event-log.md)) |
| Database | Postgres through SQLAlchemy 2.0, Alembic migrations, and the psycopg 3 driver |
| gRPC | grpcio, asyncio API, with `types-grpcio` and `types-protobuf` for pyright. Stubs in `swarmeval/proto/`, whose import path is `swarmeval.proto.<proto package>` |
| Export and offline queries | pyarrow for Parquet, DuckDB |
| Tests | testcontainers for a throwaway Postgres and RustFS. A mock OpenAI-compatible server replays scripted responses. `cryptography` (dev only) issues throwaway service certificates, so the mutual TLS tests in `mise run check` need no Go toolchain |
| Service-to-service TLS | grpcio's SSL credentials, uvicorn's `ssl_*` settings, and the standard library's `ssl` for httpx2 clients; certificates come from `swarm-certs` ([architecture.md](architecture.md#service-identity)) |

## Shared by the Go services

`edge`, `sandboxd`, `net-gateway`, and the `swarm` CLI are one Go module.

| Area | Choice |
|---|---|
| gRPC | `google.golang.org/grpc`, `google.golang.org/protobuf`; stubs generated by buf |
| Public API | `connectrpc.com/connect`: handlers and clients generated by buf for every proto package. The public contract is `proto/swarmeval/api/v1`, checked by `buf breaking` |
| Service-to-service TLS | The standard library's `crypto/tls` and `crypto/x509`, in `internal/mtls` and `internal/certs`; no PKI component |

## Shared infrastructure

| Area | Choice |
|---|---|
| Database | Postgres |
| Object storage | Any S3-compatible store, through the standard S3 API only. RustFS (Apache 2.0) in compose on a single machine; RustFS or a cloud S3 service on k8s |
| Web | React + Vite for the console and replay viewer, served through `edge` |

## Not used

| Choice | Why not |
|---|---|
| Rust | The high-concurrency proxy it was meant for is `net-gateway`, in Go. Other hot spots already run on C or Rust libraries (hashlib, orjson, pyarrow, DuckDB) |
| mitmproxy | Replaced by `net-gateway` |
| Tetragon (eBPF) | Host eBPF cannot see processes inside gVisor sandboxes, and it needs a privileged, host-wide agent on shared servers. `sandboxd` diffs host volumes after each tool call instead. A case that needs syscall-level audit uses gVisor Runtime Monitoring |
| MinIO | The community edition was archived in February 2026 and gets no security fixes |
| A local directory as object storage | A second code path next to S3. One S3 API on every deployment keeps single machine and k8s identical |
| SQLite | Ties a run to one disk, and the worker that takes a run over may be on another node |
| Celery, Ray | Scheduling is the orchestrator's own asyncio loop plus Postgres leases |
| Kafka, NATS | A run's events have one writer. Runs scale by running more of them, not by splitting one |
| LiteLLM | Model access is the `openai` SDK plus thin adapters of our own |
| `github.com/miekg/dns` (v1) | In maintenance mode. `net-gateway` uses v2 from `codeberg.org/miekg/dns` |
| `github.com/docker/docker` | Deprecated since Docker v29. `sandboxd` uses `github.com/moby/moby/client` |
| `google/gopacket` | Inactive, with fragmented forks. `net-gateway` writes pcap itself |
